# Pace

**Keep your team moving.**

ระบบ Daily Scrum ด้วย Next.js 16 + PostgreSQL (Prisma) — มี login, role ที่กำหนด level ได้เอง และหน้าภาพรวมสำหรับหัวหน้า

**Stack:** Next.js 16 (App Router, Server Actions) · React 19 · Prisma + PostgreSQL · Tailwind 4 · **zod** (กฎของฟอร์ม ใช้ชุดเดียวกันทั้งเบราว์เซอร์และ server — `src/lib/schemas.ts`) · **react-hook-form** (ตรวจรายช่องในเบราว์เซอร์ก่อนส่งเข้า server action — `src/components/zod-form.tsx`) · **axios** (อัปโหลดไฟล์พร้อมแถบความคืบหน้า — `src/lib/upload-client.ts`)

## ฟีเจอร์

- **Daily Scrum แยกต่อทีม** — ส่งได้วันละ 1 ครั้งต่อทีม (แก้ไขได้ทั้งวัน) คนที่อยู่หลายทีมมีแท็บเลือกทีม กระดานของแต่ละทีมเห็นเฉพาะสิ่งที่เขียนให้ทีมนั้น
  - ล่าสุดทำอะไรไป / วันนี้จะทำอะไร เป็น **รายการ task** — กด Enter เพื่อขึ้น task ใหม่, Backspace ในบรรทัดว่างเพื่อลบ, วางหลายบรรทัดได้
  - task ใน "วันนี้จะทำอะไร" จะขึ้นเป็น "ล่าสุดทำอะไรไป" ของเช็กอินครั้งถัดไป (ทีมเดียวกัน) ให้อัปเดต **% ความคืบหน้า** ของแต่ละ task (ติ๊ก ✓ = 100%) งานที่ยังไม่ถึง 100% จะถูกยกไป "วันนี้จะทำอะไร" อัตโนมัติพร้อม % ล่าสุด (กด × นำออกได้ถ้าไม่ทำต่อ)
  - กระดานและหน้าภาพรวมแสดง % รายงาน และ % เฉลี่ยของแต่ละคน
  - ต้องการความช่วยเหลือ (Blocker) / สิ่งที่ควรปรับปรุง / สิ่งที่ไปได้ดี
- **งาน (Tasks)** — หัวหน้าทีมมอบหมายงานให้สมาชิก (ชื่องาน, กำหนดส่ง, รายละเอียด) สมาชิกเพิ่มงานของตัวเองได้
  - งานที่ได้รับมอบหมายขึ้นเป็นปุ่มในหน้าเช็กอิน แตะเพื่อใส่ใน "ล่าสุดทำอะไรไป" หรือ "วันนี้จะทำอะไร"
  - % ที่อัปเดตในเช็กอินไหลกลับไปที่งานนั้น (หรืออัปเดตตรงจากหน้า งาน) · คนรับงานได้ push notification เมื่อมีงานใหม่
- **ความคิดเห็น** — คอมเมนต์ได้ใต้งานแต่ละงาน และใต้เช็กอิน (รวม blocker) · ลิงก์ที่วางในข้อความกดได้ · เจ้าของและคนที่อยู่ในเธรดได้ push notification
  - สมาชิกเห็นงานของทุกคนในทีม (หน้า งาน) และเช็กอินวันนี้ของเพื่อนร่วมทีม (หน้า Daily Scrum — เฉพาะงานและ blocker ส่วน reflection เห็นเฉพาะหัวหน้า)
  - ลบได้เฉพาะคนเขียนเองหรือคนที่ดูแลทีมนั้น
- **ไฟล์แนบ (ชั่วคราว)** — แนบไฟล์ได้กับงาน (ตอนมอบหมายหรือภายหลัง) และในความคิดเห็น สูงสุด 20 MB ต่อไฟล์ ครั้งละ 5 ไฟล์ · ลิงก์ในรายละเอียดงานและความคิดเห็นกดได้
  - ไฟล์ถูก **ลบเองหลัง 7 วัน** (`ATTACHMENT_TTL_DAYS`) — คลิกขวาที่ไฟล์ (หรือกด ⋯ บนมือถือ) → **Mark ว่าสำคัญ** เพื่อเก็บถาวร ไฟล์ที่ mark แล้วรวมอยู่ในหน้า **ไฟล์สำคัญ** แยกตามทีม
  - เก็บใน Supabase Storage bucket `file` (ต้องเป็น private · เปลี่ยนชื่อได้ด้วย `SUPABASE_ATTACHMENT_BUCKET`) เบราว์เซอร์อัปโหลด/ดาวน์โหลดตรงผ่าน signed URL อายุสั้น · ต้องตั้ง `SUPABASE_URL` + `SUPABASE_SECRET_KEY` ไม่งั้นปุ่มแนบไฟล์จะไม่แสดง
  - ลบไฟล์หมดอายุ (และเก็บกวาดตัวนับ rate limit / แจ้งเตือนเก่า) ด้วย cron `GET /api/cron/cleanup-files` (ใน `vercel.json` รันทุกวัน 02:00 เวลาไทย, ใช้ `CRON_SECRET` เดียวกับแจ้งเตือน)
- **ภาพรวมทีม** (หัวหน้า) — ส่งแล้วกี่คน, blockers ที่ต้องปลดล็อก, รวม not work / work well, การ์ดรายคน, ใครยังไม่ส่ง, ตารางการส่งย้อนหลัง 7 วัน, ย้อนดูวันก่อน ๆ และประวัติรายคน
- **ทีมซ้อนกันได้ 2 ชั้น** (ทีมใหญ่ → ทีมย่อย) และคนหนึ่งอยู่ได้หลายทีม
- **สิทธิ์กำหนดรายทีม** (`TeamMember.access`) — ไม่มีใครเห็นข้อมูลของทีมที่ตัวเองไม่ได้อยู่

| สิทธิ์ในทีม | ทำอะไรได้ |
|-------------|-----------|
| สมาชิก (MEMBER) | เช็กอิน, เห็นงานและเช็กอินของเพื่อนร่วมทีม, แสดงความคิดเห็น |
| หัวหน้าทีม (LEAD) | + เห็นภาพรวมและมอบหมายงานในทีมนั้นและทีมย่อย |
| เจ้าของทีม (OWNER) | + จัดการสมาชิกและตั้งค่าทีม |

  - **ชื่อบทบาท** ตั้งเองได้ต่อทีม (`TeamMember.title` เช่น Dev, PM, PO, Scrum Master) ไม่มีผลต่อสิทธิ์
  - สมาชิกที่ `participates = false` คือผู้ดูแลอย่างเดียว ไม่ต้องเช็กอินและไม่ถูกนับในภาพรวม
  - หน้าภาพรวมดูได้ทีละทีม (ไม่มี "ทุกทีม")
- **ทีมและคำเชิญ** (หน้า ทีม) — ใครก็สร้างทีมของตัวเองได้และเป็นเจ้าของทีม เจ้าของทีมแก้สิทธิ์/ชื่อบทบาท/การเช็กอินของสมาชิก เอาสมาชิกออก และสร้างทีมย่อยได้
  - **เชิญด้วยอีเมล** — หัวหน้าทีมเชิญสมาชิกได้ เจ้าของทีมเชิญเป็นหัวหน้าได้ · ได้ลิงก์คำเชิญ (ใช้ครั้งเดียว อายุ 7 วัน) ให้คัดลอกส่งเอง และส่งอีเมลให้ด้วยถ้าตั้งค่า Resend
  - คนที่มีบัญชีและยืนยันอีเมลแล้ว เห็นคำเชิญในหน้า ทีม กดรับได้เลยโดยไม่ต้องเปิดอีเมล · ช่องอีเมลตอนเชิญเลือกจากคนที่เคยเชิญ/เคยร่วมทีมกันได้
- **ปฏิทินงาน** (หน้า ปฏิทิน) — ตารางรายเดือนตามกำหนดส่ง (งานของฉัน / ของคนอื่น / เลยกำหนด / เสร็จแล้ว) กดวันเพื่อเพิ่มงานในวันนั้น · รายการเรียงตามวันให้เลื่อนกำหนดได้ และรายการงานที่ยังไม่มีกำหนดส่งให้ใส่วัน (จอเล็กใช้รายการแทนตาราง)
- **พื้นที่ส่วนตัว** — ทุกบัญชีมีพื้นที่ของตัวเองโดยไม่ต้องมีทีม (สร้างให้อัตโนมัติ) ใช้ลงงานพร้อมกำหนดส่ง, บันทึกประจำวัน/อัปเดตความคืบหน้า, โน้ต และสถิติ ได้เหมือนในทีม เห็นเฉพาะเจ้าของ
  - เบื้องหลังคือทีมที่มี `Team.personalOfId` (เจ้าของคนเดียว เชิญ/จัดการ/ลบไม่ได้ ไม่ขึ้นในภาพรวมทีม และไม่มีการเตือนเช็กอิน) จึงใช้โค้ดชุดเดียวกับทีมทั้งหมด — ดู `src/lib/personal.ts`
- **โน้ต (ฐานความรู้แบบ Obsidian)** — หน้า โน้ต: สร้างโฟลเดอร์ซ้อนกันและโน้ต เขียนด้วย**ตัวแก้ไขแบบเห็นผลทันที** (ปุ่มหัวข้อ, ตัวหนา, รายการ, สิ่งที่ต้องทำ, ตาราง, ลิงก์ — ไม่ต้องรู้ Markdown; เก็บเป็น Markdown เบื้องหลัง) ในทีมทุกคนอ่านและแก้ได้ เชิญคนเพิ่มผ่านคำเชิญเข้าทีมเดิม · ลิงก์ไปโน้ต/งานแสดงเป็นป้ายในตัวแก้ไข (`src/components/notes/link-chips.ts`)
  - **เชื่อมความสัมพันธ์** — `[[ชื่อโน้ต]]` (หรือ `[[ชื่อโน้ต|ข้อความ]]`) ลิงก์ไปโน้ตอื่น · ลิงก์ไปโน้ตที่ยังไม่มีคลิกเพื่อสร้างได้ · แต่ละโน้ตแสดง "โน้ตที่ลิงก์มาที่นี่" · เปลี่ยนชื่อโน้ตแล้วลิงก์ในโน้ตอื่นแก้ตาม
  - **เชื่อมกับงาน** — เขียน `#เลขงาน` ในโน้ต จะลิงก์ไปงานนั้น และโน้ตจะขึ้นใต้งานในหน้า งาน
  - **แผนผังความสัมพันธ์** ของโน้ตและงานทั้งทีม · ค้นหาในชื่อและเนื้อหา · ย้าย/ลบ (ลบแบบซ่อน)
  - แก้พร้อมกันสองคน: คนที่บันทึกทีหลังจะได้รับแจ้งว่ามีเวอร์ชันใหม่กว่า ไม่เขียนทับกัน (ยังไม่ใช่การพิมพ์พร้อมกันแบบ real-time)
  - ไวยากรณ์ลิงก์อยู่ที่ `src/lib/note-links.ts` · ความสัมพันธ์เก็บในตาราง `NoteLink`
- **งานในเช็กอิน = งานจริง** — บรรทัดที่พิมพ์ในเช็กอินจะถูกสร้างเป็นงานที่มอบหมายให้ตัวเอง (ขึ้นในหน้า งาน, ติดตาม % ที่เดียวกัน, แก้ชื่อได้จากเช็กอิน) · ทุกงานมีเลขรันต่อทีม (`#12`)
  - การ์ดเช็กอินที่มีงานเกิน 5 รายการจะพับส่วนที่เหลือไว้ (งานที่ยังไม่เสร็จขึ้นก่อน) · ปุ่มงานค้างในฟอร์มแสดง 6 รายการแรก
- **ห้องประชุมของทีม** — เจ้าของทีมวางลิงก์ Google Meet / Zoom ในหน้าจัดการทีม สมาชิกเห็นปุ่ม "เข้าห้องประชุม" ในหน้า Daily Scrum และภาพรวมทีม (ทีมย่อยใช้ลิงก์ของทีมแม่ถ้าไม่ได้ตั้งเอง)
- **เหตุผลของการอัปเดต %** — ตอนอัปเดตความคืบหน้าในหน้า งาน ใส่เหตุผล/หมายเหตุได้ (ไม่บังคับ) ทุกครั้งที่ % เปลี่ยนจะบันทึกลงเธรดความคิดเห็นของงาน (เช่น `40% → 65%`) รวมถึงที่อัปเดตผ่านเช็กอิน
  - แจ้งเตือนในแอป + push ถึงคนรับงาน คนมอบหมาย และหัวหน้า/เจ้าของของทีมนั้นและทีมแม่ (ไม่ส่งอีเมล เพราะเกิดบ่อย · อัปเดตผ่านเช็กอินไม่แจ้งซ้ำ)
- **สถิติการมีส่วนร่วม** (หน้า สถิติ, ช่วง 7/30/90 วัน) — อัตราเช็กอินจากวันทำงานจันทร์–ศุกร์นับตั้งแต่วันเข้าทีม, จำนวนวันส่งต่อเนื่อง, งานที่เสร็จ/ค้าง/เลยกำหนด, ความคิดเห็น, blocker ที่แจ้ง
  - ทุกคนเห็นของตัวเองและค่าเฉลี่ยทีม · ตารางรายคนเห็นเฉพาะหัวหน้า/เจ้าของทีม · ยังไม่รู้จักวันหยุดนักขัตฤกษ์
- **ลบทีม** — เจ้าของทีมลบทีมได้จากหน้าจัดการทีม (ต้องพิมพ์ชื่อทีมยืนยัน) ลบงาน เช็กอิน ความคิดเห็น ไฟล์แนบ และคำเชิญของทีมนั้นทั้งหมด
- **แจ้งเตือน** — กระดิ่งในแอปพร้อมจำนวนที่ยังไม่อ่าน และหน้า แจ้งเตือน (งานใหม่, ความคิดเห็น, คำเชิญ, ทีมถูกลบ) · ส่ง push ไปเครื่องที่เปิดไว้ และส่งอีเมลถ้ายืนยันอีเมลแล้ว (ปิดได้ที่หน้า บัญชี)
- **ความปลอดภัยของบัญชี** — "จดจำฉันไว้" = อยู่ในระบบ 30 วัน (ไม่ติ๊ก = หลุดเมื่อปิดเบราว์เซอร์) · เปลี่ยน/รีเซ็ตรหัสผ่านแล้วเครื่องอื่นหลุดออก · จำกัดจำนวนครั้งของ login (10 ครั้ง/บัญชี/15 นาที), สมัคร และลืมรหัสผ่าน
- **สมัครเอง / ลืมรหัสผ่าน** — `ALLOW_SIGNUP=true` เปิดให้ใครก็สมัครได้ (ค่าเริ่มต้นปิด: สมัครได้เฉพาะคนที่มีลิงก์คำเชิญ) · ลืมรหัสผ่านและยืนยันอีเมลใช้ได้เมื่อตั้ง `RESEND_API_KEY` + `EMAIL_FROM`
- **โปรไฟล์** — เปลี่ยนชื่อที่แสดงและรูปโปรไฟล์ได้เองที่หน้า บัญชี (รูปถูกครอป/ย่อเป็น 256×256 ในเบราว์เซอร์) · เก็บใน Supabase Storage bucket `profile_images` (private) ถ้าตั้ง `SUPABASE_URL` + `SUPABASE_SECRET_KEY` ไม่งั้นเก็บในตาราง `Avatar`
- **ผู้ดูแลแพลตฟอร์ม** — role ที่ level ≥ 100 เข้าหน้า Admin เพื่อจัดการผู้ใช้ / role / ทีม ทั้งระบบ (เกณฑ์อยู่ที่ `src/lib/permissions.ts`) · Admin กำหนด role/level สูงกว่าตัวเองไม่ได้ และลดสิทธิ์/ปิดบัญชีตัวเองไม่ได้

## หน้าตาและเมนู

- **Design tokens** อยู่ที่ `src/app/globals.css` (`@theme` + `:root`) — สี `primary/surface/muted-foreground/success/warning/danger`, เงา `shadow-soft/raised/overlay` มาจากงานออกแบบใน Lovable (โปรเจกต์ต้นแบบ ดู `docs/lovable-redesign-brief.md`) component ใหม่ให้ใช้ชื่อ token แทนสี slate/indigo ตรง ๆ
- **เมนูจัดเป็นหมวด** (`src/app/(app)/layout.tsx`): เช็กอิน · งาน (รายการ/ปฏิทิน/ไฟล์สำคัญ) · โน้ต · ทีม (ภาพรวม/สถิติ/ทีมและคำเชิญ) — มือถือมี 5 ปุ่มล่าง และแท็บย่อยของหมวดที่หัวหน้า (`SectionTabs`)
- **ตัวเลือกพื้นที่** (`SpaceSwitcher`) อยู่ที่เดียวใน layout จำค่าใน cookie `pace_space` ทุกหน้าใช้ตาม (`src/lib/space.ts`) — ลิงก์ที่มี `?team=` ยังใช้ได้และมีผลเหนือ cookie
- **Tooltip / HelpTip** (`src/components/tooltip.tsx`): Tooltip สำหรับปุ่มไอคอน (ชื่อ + คีย์ลัด), HelpTip "?" สำหรับอธิบายแนวคิด แตะได้บนมือถือ
- **หน้า งาน**: แถวกะทัดรัด (วงแหวน % กดเพื่อปิดงาน, เลขงาน, ชื่อ, กำหนดส่ง, จำนวนความคิดเห็น/ไฟล์/โน้ต) — รายละเอียดทั้งหมดอยู่ในแผง `?task=เลขงาน` (ด้านข้างบนจอใหญ่ เต็มจอบนมือถือ) มีแถบเลื่อน % พร้อมปุ่มลัด 0/25/50/75/เสร็จ · เพิ่มงานด้วยชื่ออย่างเดียวแล้วกด Enter
- **หน้า วันนี้** (`/standup`): งานที่ถึงกำหนด/เลยกำหนดจากทุกพื้นที่ → เช็กอินประจำวัน · การ์ดเริ่มต้นใช้งานสำหรับผู้ใช้ใหม่ (ปิดแล้วจำใน localStorage)
- **ตัวแก้ไขโน้ต** (`src/components/notes/editor-menus.tsx`): พิมพ์ `/` = เมนูคำสั่ง, `[[` = เลือกโน้ต (หรือเสนอสร้างใหม่), `#` = เลือกงาน · แถบเครื่องมือลอยเมื่อเลือกข้อความ (เฉพาะอุปกรณ์ที่ใช้เมาส์)
- **แจ้งเตือน**: กระดิ่งในเมนูด้านข้างเปิดรายการล่าสุดเป็น dropdown (มือถือใช้หน้าเต็ม)
- **อ่านโน้ตบนจอสัมผัส** ปิดการเลือกข้อความไว้ก่อนเพื่อให้เลื่อนอ่านได้ลื่น มีปุ่ม "เลือกข้อความเพื่อคัดลอก" (`ReadingSurface`)

ตั้งค่าอยู่ที่ `src/app/manifest.ts` · ไอคอนอยู่ใน `public/icon-*.png` · ยังต้องมีอินเทอร์เน็ตตอนใช้งาน (service worker `public/sw.js` ใช้รับ push เท่านั้น ไม่ได้ cache หน้าเว็บ)

## แจ้งเตือนเช็กอิน (Push notification)

ผู้ใช้เปิดเองที่หน้า **บัญชี → แจ้งเตือนเช็กอิน** (ตั้งค่าแยกรายเครื่อง) ระบบจะเตือนเฉพาะคนที่ยังไม่ได้เช็กอินของวันนั้น

- เวลาเตือนกำหนดใน `vercel.json` (`0 2 * * 1-5` = 09:00 เวลาไทย จันทร์–ศุกร์) — แผน Hobby ของ Vercel รันได้วันละครั้งและเวลาอาจคลาดได้ภายในชั่วโมงนั้น
- ต้องตั้ง env: `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` (สร้างด้วย `npx web-push generate-vapid-keys`), `VAPID_SUBJECT`, `CRON_SECRET`
- ถ้าไม่ได้ใช้ Vercel (เช่น Docker) ให้ตั้ง cron ภายนอกเรียก `GET /api/cron/checkin-reminder` พร้อม header `Authorization: Bearer $CRON_SECRET`
- iPhone รับแจ้งเตือนได้เมื่อติดตั้ง Pace ลงหน้าจอโฮมแล้ว (iOS 16.4+)

## Environment variables

|--------|---------|

| `DIRECT_URL` | connection string สำหรับ migrate (local/docker ใช้ค่าเดียวกับ `DATABASE_URL`) |
| `AUTH_SECRET` | secret สำหรับเซ็น session (≥ 32 ตัวอักษร) |
| `APP_TIMEZONE` | timezone ที่ใช้ตัดวัน (default `Asia/Bangkok`) |

| `COOKIE_SECURE` | ตั้ง `false` เฉพาะตอนรัน production ผ่าน http |
| `SKIP_SEED` | `true` = ไม่รัน seed ตอน start |
| `ALLOW_SIGNUP` | `true` = เปิดให้สมัครเองโดยไม่ต้องมีคำเชิญ |

| `APP_URL` | URL หลักของเว็บ ใช้สร้างลิงก์คำเชิญ/อีเมล (บน Vercel ไม่ต้องตั้ง ใช้โดเมน production ให้เอง) |

## Deploy ฟรีด้วย Vercel + Supabase

1. **Supabase** — สมัครที่ [supabase.com](https://supabase.com) → New project (region Southeast Asia / Singapore) → จดรหัสผ่าน database ไว้
2. ไปที่ **Connect** (ปุ่มด้านบนของ project) → แท็บ **ORMs → Prisma** จะได้ 2 URL:
   - `DATABASE_URL` — Transaction pooler (port **6543**) ต่อท้าย `?pgbouncer=true&connection_limit=1`
   - `DIRECT_URL` — Session pooler (port **5432**) ใช้ตอน migrate
3. **Vercel** — [vercel.com/new](https://vercel.com/new) → Import repo นี้ → เพิ่ม Environment Variables:

| ตัวแปร | ค่า |
|--------|-----|
| `DATABASE_URL` | Transaction pooler URL (6543) |
| `DIRECT_URL` | Session pooler URL (5432) |
| `AUTH_SECRET` | `openssl rand -base64 32` |
| `APP_TIMEZONE` | `Asia/Bangkok` |
| `SEED_ADMIN_EMAIL` / `SEED_ADMIN_PASSWORD` | admin คนแรก |

4. กด Deploy — script `vercel-build` จะรัน migration + สร้าง admin (ครั้งแรกเท่านั้น) + build ให้เอง
5. เปิด `https://<project>.vercel.app` แล้ว login ด้วย admin ที่ตั้งไว้ · push เข้า `main` = deploy ใหม่อัตโนมัติ

หมายเหตุ
- `vercel.json` กำหนดให้ function รันที่ `bom1` (Mumbai) ให้อยู่ region เดียวกับ Supabase — ถ้าย้าย DB ไป region อื่น ให้เปลี่ยนตามกัน (เช่น Singapore = `sin1`) ไม่งั้นทุก query จะช้ามาก
- ตารางเปิด Row Level Security ไว้ (migration `0002_enable_rls`) เพื่อไม่ให้เข้าถึงข้อมูลผ่าน Supabase Data API ได้ — แอปต่อผ่าน Prisma จึงไม่กระทบ
- Supabase free จะ **pause project ถ้าไม่มีการใช้งาน 7 วัน** (กด Restore ใน dashboard ได้) — ถ้าทีมใช้ทุกวันทำงานจะไม่เจอ
- Vercel Hobby ฟรีสำหรับใช้งานที่ไม่ใช่เชิงพาณิชย์

## ภาษา (ไทย / English)

- ผู้ใช้เลือกภาษาได้ที่ รูปโปรไฟล์ → บัญชีและการตั้งค่า → ภาษา (และที่หน้าเข้าสู่ระบบ) ค่าถูกจำใน cookie `pace_lang` ของเบราว์เซอร์ และใน `User.locale` ของบัญชี — เข้าสู่ระบบจากเครื่องใหม่จะได้ภาษาของบัญชี อีเมลและแจ้งเตือนส่งตามภาษาของผู้รับ
- ข้อความต้นฉบับในโค้ดเป็นภาษาไทย และใช้ข้อความไทยนั้นเป็นคีย์ของคำแปล คำแปลอังกฤษอยู่ที่ `src/lib/i18n/en.ts` (ไม่มีคำแปล = แสดงข้อความไทย)
- เพิ่มข้อความใหม่: server component ใช้ `tr("ข้อความ")` จาก `@/lib/i18n/server` · client component ใช้ `const tr = useT()` จาก `@/components/i18n` · server action ใช้ `const tr = await getTr()` · ข้อความถึงคนอื่น (อีเมล/แจ้งเตือน) ใช้ `trFor(user.locale)` · ตัวแปรเขียนเป็น `{0}` `{1}` เช่น `tr("ค้างอยู่ {0} งาน", [n])` แล้วเพิ่มคำแปลใน `en.ts`
- ข้อความ `{ error }` / `{ ok }` แบบคงที่จาก server action ไม่ต้องครอบ — `FormMessage` แปลให้ตอนแสดง แค่เพิ่มคำแปลใน `en.ts`
- วันที่ใช้ `formatDateKey` / `formatDateTime` จาก `@/lib/format-dates` (ตามภาษา) · ไฟล์ที่ client component import ห้าม import `@/lib/i18n/server`

## เชื่อมต่อผู้ช่วย AI (MCP)

Pace เป็นเซิร์ฟเวอร์ [MCP](https://modelcontextprotocol.io) ในตัว ให้ผู้ช่วย AI เช่น Claude ดูและจัดการงาน โน้ต และเช็กอินได้

- ที่อยู่: `POST /api/mcp` (Streamable HTTP แบบไม่เก็บสถานะ — ตอบเป็น JSON ไม่มี SSE)
- ยืนยันตัว: `Authorization: Bearer <โทเคน>` — ผู้ใช้สร้างโทเคนเองที่ บัญชี → เชื่อมต่อผู้ช่วย AI (ตาราง `ApiToken` เก็บเฉพาะ hash) เลือกแบบอ่านอย่างเดียวได้
- สิทธิ์: ทุกเครื่องมือทำงานในนามเจ้าของโทเคน ใช้กฎชุดเดียวกับหน้าเว็บ (`src/lib/task-ops.ts`) จำกัด 120 คำขอต่อนาทีต่อคน
- เครื่องมือ (`src/lib/mcp.ts`): `list_spaces` `list_tasks` `get_task` `create_task` `update_task` `list_notes` `read_note` `create_note` `update_note` `get_checkins`

```bash
claude mcp add --transport http pace https://<โดเมน>/api/mcp --header "Authorization: Bearer <โทเคน>"
```

ยังไม่รองรับ OAuth — โปรแกรมที่เพิ่มเซิร์ฟเวอร์ได้เฉพาะแบบ OAuth (เช่น ตัวเชื่อมต่อแบบกำหนดเองบนเว็บ claude.ai) จึงยังใช้ไม่ได้
